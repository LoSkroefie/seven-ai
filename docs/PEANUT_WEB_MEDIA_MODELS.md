# Peanut owner web, media, and model contract

This document describes Seven's private Peanut browser experience. It is
separate from the Windows desktop voice and vision documentation.

## Browser transport

- The page and API are same-origin. Apache exposes `/seven/` and the compatible
  `/3dwebsite/seven-api/` route through the loopback-only gateway.
- Chat uses `POST api/turn`, bounded `GET api/turn?id=...` polling, and
  `turn_status` server-sent events from `GET api/events`.
- There is no WebSocket transport. SSE is an accelerator; polling remains the
  completion fallback.
- A turn has one terminal consumer in the page. Concurrent SSE and polling
  callbacks share one in-flight request, and terminal turn IDs are ignored
  after completion, failure, or rejection.
- Authentication uses the secure owner session cookie, exact-Origin checks,
  and an `X-CSRF-Token` header on state-changing requests.

## Reply and voice behavior

- A completed text or image reply always returns the presence state to `ready`
  unless another turn remains pending. This does not depend on speech support.
- Browser speech synthesis is **muted by default**. The owner must explicitly
  enable it for the current page.
- Speech is generated by the browser and operating system. It is not a
  server-generated or portable Seven voice, so the available voice and sound
  can differ by device.
- Muting speech cancels the current utterance without discarding the text
  reply.

## Microphone and transcription

- The owner holds the microphone control to record. The client negotiates the
  first browser-supported type from WebM/Opus, Ogg/Opus, MP4, and WebM.
- Recording data is collected in one-second chunks.
- A recording stops automatically after 60 seconds.
- The client cancels a recording before upload if it would exceed 8,000,000
  bytes. The gateway independently enforces the same byte limit and validates
  the media signature.
- The raw recording is sent to `POST api/media/audio`. Peanut transcribes it
  locally with Faster Whisper. The returned transcript is placed in the
  composer for owner review; it is never sent to Seven automatically.
- Page hiding, logout, and page exit stop every microphone track and discard an
  unfinished recording.

## Camera and image analysis

- Camera access is owner-initiated and captures one JPEG snapshot.
- Snapshot dimensions must be finite and positive. The client bounds width to
  1,280 pixels and both dimensions to 8,192 pixels.
- A missing canvas context, encoding failure, invalid dimensions, or JPEG over
  5,000,000 bytes is rejected locally. The gateway repeats signature,
  dimension, and byte validation.
- Camera tracks stop after capture whether encoding succeeds or fails. Page
  hiding, logout, and page exit also stop every track.
- The JPEG is sent to `POST api/media/jpeg`, analyzed through Seven's
  loopback-only `/vision` endpoint, and not retained by the gateway.

## Peanut models

The checked-in Peanut profile uses:

- text: `qwen3:0.6b`
- vision: `hf.co/ggml-org/SmolVLM-500M-Instruct-GGUF:Q8_0`
- Ollama: loopback `127.0.0.1:11435`, one loaded model at a time

The 2026-07-29 read-only live inventory also found `qwen3-vl:2b` already
installed but not configured. It is a candidate, not a production selection.
The corresponding official Hugging Face GGUF is
`Qwen/Qwen3-VL-2B-Instruct-GGUF:Q4_K_M`.

Vision promotion requires a fixed comparison corpus covering ordinary objects,
UI screenshots and OCR, maps or charts, low light, and ambiguous scenes.
Record cold and warm latency, supported observations, hallucinations, peak
service memory, swap change, and service restarts. Promote only after the
candidate:

1. beats the current 500M model on the agreed image checks;
2. stays below the `seven-ollama.service` memory limit;
3. does not create unacceptable host load or swap pressure;
4. passes a service restart and an explicit known-good rollback.

Do not treat the generic Ollama endpoint retry as a model-quality fallback.
Vision fallback must remain modality-aware; a text-only loaded model is not a
valid substitute for a failed vision model.

## Verification

Run the static and executable browser-like contract together:

```powershell
python -m pytest -q deploy/peanut/tests/test_static_owner_experience.py
```

Run the JavaScript contract directly when diagnosing browser logic:

```powershell
node --test deploy/peanut/tests/test_seven_client_runtime.mjs
```

The executable contract covers gateway error mapping, muted-TTS reply
settlement, recorder MIME and byte limits, snapshot dimensions, and concurrent
terminal-fetch deduplication. It does not replace a real-browser permission
test with an actual camera and microphone or a live model-generated image
result.
